# 第三轮：显式概率融合，未超过第二轮

## 假设与变更

R2整体AUC为0.798241。数值诊断显示，一个固定的“题目难度 log-odds＋近期/总体准备度偏移”参考评分在验证样本上AUC约0.820513，因此尝试把R2的宽泛融合指令改为明确计算步骤。

版本：configs/prompts/round3.yaml，kt_r3_explicit_odds_fusion_v1。保持R2完全相同的历史、计数和训练先验；指定近期/总体偏移权重0.7/0.3，先做小样本平滑，再按log-odds组合，只允许强目标知识点证据作小幅修正。权重是启发式，不是训练拟合出的最优系数。参考评分已在验证集观察，因此不是独立检验。

## 总结与复盘

R3整体AUC相对R2下降0.031394，logloss与Brier也回退，因此不采用。学生级AUC均值和ACC虽改善，但不能替代用户优先要求的整体AUC；同时学生统计只有16个有效学生。

概率唯一值从R2的95增至141，却没有改善排序。输出更多小数位不等于更高预测质量。

离线逐条按提示公式精确重算后，模型输出相对参考概率的平均绝对偏差约0.127774；221条中173条偏差超过0.05。仅增加公式文字，没有使模型可靠执行算术及受限修正。这是本次失败的重要观察，不应把0.820513的外部精确评分当作R3实际AUC。

若以后继续，可将确定性的概率运算放在代码中，把大模型限定为有证据的残差修正，并与简单KT/统计基线比较；这属于新的混合方法，需要另行版本化与完整评估。本轮没有把这种想法伪装成已实现增益。

## 决策

三轮目标1已完整执行，按验证整体AUC锁定R2，选择记录在独立测试调用前保存。R3作为失败候选保留全部请求响应及诊断；没有自动把最新版本当作最佳。

不据此宣称AUC已经达到上限，也没有进入节省token的阶段。下一步只对锁定R2与B0作一次独立测试对照，不用测试结果继续挑选prompt。
