# KT 相邻历史前缀缓存探索

日期：2026-10-18。用户授权本轮最多 0.50 USD，允许不同供应商及新模型 `qwen/qwen3.8-27b` 的缓存探索。

**已验证：同一学生逐步预测时，相同历史前缀可以获得缓存输入折扣。** 收益取决于输入顺序、供应商后端和历史是否开始滚动。默认推理输入尚未修改；以下变体只存在于独立实验工具。

## 费用与执行范围

- 77 次远程请求，均收到响应，76 次生成有效概率；1 次返回 `{}`，严格解析失败，但费用仍计入。
- 所有响应都有费用，合计 **0.019365184 USD**，未知费用项 0。使用授权额度约 3.87%，剩余 0.480634816 USD，结束测量后没有继续花费。
- 两个模型、六个供应商、八个模型/端点组合；包括 Qwen3.8 的 Chutes、NEAR AI、DeepInfra、AkashML、Parasail，以及 Qwen3.6 的 Darkbloom、AkashML、Parasail。
- 本轮账本独立于之前重复请求测试，不把此前调用混入本轮对照。所有预热、相同请求复测、失败解析及布局对照费用均包含在上述总额。

## 样本与实验设计

从此前选中的 NIPS 学生中，取完整序列足够长的一名，使用真实作答逐步预测。绝不使用上一题预测概率代替已经观察到的真实答案。模型请求只有题目/知识点 ID 和允许看到的历史作答，不含学生 ID、当前或未来标签。

主协议保持 `pykt_window`，maxlen=200，对应最多 199 条历史。以下 index 是原序列中从 0 开始的事件位置。

| 阶段 | 目标 index | 历史范围 |
|---|---|---|
| 增长期 | 150、151、152 | 从 0 开始，分别 150、151、152 条 |
| 窗口将满 / 已满 | 198、199 | 从 0 开始，分别 198、199 条 |
| 窗口滚动 | 200、201、202 | 从 1、2、3 开始，各 199 条 |

每个请求都重建其完整合法历史；目标 index 跳跃时，不省略中间真实作答。同一 case 串行发送，间隔 1 秒；固定 provider.only、关闭 fallback，使用独立 x-session-id 维持会话路由。输出上限 128、temperature=0、关闭 reasoning。支持 response_format 的端点要求 JSON 对象。没有自动重试，也没有显式 cache_control。

比较三种布局：

1. `current_first`：现有 canonical JSON，current_item 在 history 前。
2. `history_first`：实验性逐行 JSON 历史，当前题在最后；语义相同，但分隔格式增加输入 token。
3. `history_first_json`：紧凑 JSON，仅调换顶层两个键的顺序，保持相同字段、数据和字符数，当前题在最后。

同一增长阶段最后目标的完整重复仅作辅助对照，不算新的 KT 目标。相邻目标统计和费用节省汇总排除这些重复，实验总费用则包含它们。不同 case 可能复用之前已经建立的缓存，第一次观察不等于已证明的冷缓存。

## 最有解释力的对照：紧凑 JSON

Qwen3.8 27B / Chutes fp8，三个相邻增长目标：

| 布局 | 各目标输入 token | 各目标缓存读取 token | 三次输入费用 USD | 三次总费用 USD |
|---|---|---|---:|---:|
| 原布局，当前题在前 | 2490、2506、2522 | 0、0、0 | 0.000293202 | 0.000335702 |
| 紧凑 JSON，历史在前 | 2490、2506、2522 | 0、1600、1600 | 0.000180882 | 0.000222132 |

两组输入 token 数完全相同，输入费用降低 **38.31%**。这包含增长阶段第一次未命中的费用，没有只挑选后两次命中请求。观察到的总费用降低约 33.83%，但输出 token 也有变化，不能把总费用变化全部归因于输入缓存。

该端点当时普通输入 0.039 USD/M、缓存读取 0.0039 USD/M。第二次请求的输入费用可直接核对：

```text
输入 token 2506，缓存读取 1600
未缓存输入费用 = 2506 × 0.039 / 1,000,000 = 0.000097734 USD
实际输入费用 = 906 × 0.039 / 1,000,000 + 1600 × 0.0039 / 1,000,000
             = 0.000041574 USD
```

这些数字与响应 cost_details 的输入分项一致，证明此处是服务端输入费用折扣，不是本地直接取旧结果。

## 窗口滚动会破坏公共起始前缀

历史在前、紧凑 JSON 的边界结果：

| 模型 / 端点 | index 198 | index 199 | index 200 | index 201 | index 202 |
|---|---:|---:|---:|---:|---:|
| Qwen3.8 / Chutes | 1600 | 2400 | 0 | 0 | 0 |
| Qwen3.6 / AkashML | 2112 | 3168 | 0 | 0 | 0 |

表中为 cached_tokens。index 200 开始移除最早记录，虽然仍有 198 条历史与上一请求重叠，但它们不再位于同一输入开头。此次两个端点均未从滚动后的三个相邻请求获得缓存读取。

逐行布局在 Qwen3.8 的 Chutes、NEAR AI、DeepInfra 上也呈现同样的边界趋势：滚动后为 0。原布局在这三个端点的增长期对照也全部为 0。

这支持将“增长期”和“滚动期”分开估算，不能给整个测试集套用 38.31%。更不能为了保留前缀悄悄换成无限历史协议。本轮没有发送预留的 full_prefix 样本，也未测试该协议的命中率。

## 不同供应商的表现

首次筛选使用逐行历史布局、相邻目标 150→151→152，各请求的 cached_tokens 如下。重复 index 152 的辅助对照单独列出，不计入前面三条。

| 模型 | 端点 | 三条相邻目标 | 相同目标重复对照 |
|---|---|---|---:|
| Qwen3.8 27B | Chutes fp8 | 0、1600、1600 | 1600 |
| Qwen3.8 27B | NEAR AI fp8 | 0、1600、0 | 2816 |
| Qwen3.8 27B | DeepInfra bf16 | 0、0、2352 | 0 |
| Qwen3.8 27B | AkashML fp8 | 0、0、0 | 2352 |
| Qwen3.8 27B | Parasail fp8 | 0、0、0 | 2352 |
| Qwen3.6 35B A3B | Darkbloom fp4 | 0、0、0 | 0 |
| Qwen3.6 35B A3B | AkashML fp8 | 0、0、2112 | 2112 |
| Qwen3.6 35B A3B | Parasail fp8 | 0、0、2112 | 2112 |

供应商固定及会话标识没有使命中变成确定事件。同一端点有时相邻请求命中、随后完整重复反而不命中；不同后端工作节点、缓存分块、写入时机等是可能因素，本次没有取得足够证据确定原因。不能把“模型支持缓存”当作每条请求的保证。

Qwen3.6 / AkashML 的紧凑增长对照为 0、0、0，但稍后边界目标又命中 2112、3168。这进一步说明不能只用一次短序列判定该模型能否缓存，或用单次最高命中量估算生产收益。

## 成本、输出与实验可比性

输入折扣按每次实际输入 token 数乘以当时端点普通价建立反事实基线，再减去响应中的实际输入费用。只在有明确响应字段时计算；缺失值不补零。输出费用、无效概率结果和复测费用另外保留。

逐行历史比紧凑 JSON 输入更长。只比较它的命中率与原布局会忽略这部分额外成本；因此增加了相同字符数、相同输入 token 数的紧凑 JSON 对照。

紧凑 JSON 与原布局的 JSON 数据解析后相等，但语言模型仍可能对顺序敏感。Chutes 三条增长目标中，一条概率相差 0.07，另两条相同；温度 0 也不能保证后端完全确定。这里没有声称缓存提升预测质量，也没有用单个学生推断整体 AUC。若将候选布局合入生产，必须版本化输入模板并重新评估指标。

## 预算和可追溯产物

工具 `tools/explore_adjacent_cache.py` 使用持久化 budget.json，固定本轮上限 0.50 USD；每次发请求前，先将保守费用预留写入磁盘。预留根据输入字节数加 4096 的额外额度、最大输出 token 和当时价格计算，再乘 4；若有更高写入价也计入。已返回费用替换该次预留，未知计费请求始终保留整个预留。新请求若会使“已知费用＋未知预留＋本次预留”超过上限则拒绝发送。

账本由进程锁保护，串行请求；中断或已完成的 job 不会自动再次发送。价格估算及预留是客户端保护，不是服务端设置的账户扣费硬限额；本轮实际费用远低于预留上限，全部响应费用已核对。

每个 attempt 独立保存 request.json、response.body.txt、response.json、context.json、result.json 与哈希清单。context 包含 plan_id、样本身份、请求位置、历史范围、布局、会话标识、价格端点和脚本指纹。Authorization 不落盘；响应正文落盘前脱敏。样本和标签独立存于本地 sample_evidence，当前答案不进入请求。

本地完整产物：`runs/adjacent_cache_20261018/`。其中 metadata 保留官方端点响应，plans 保留执行计划，code 保留实际脚本版本，summary.json 为离线统计结果。官方价格中的促销可能变化，例如本次 DeepInfra bf16 采用当日折后价格。用于估算器的 Qwen3.8 五个已测端点价格另存于 `configs/pricing/qwen3.8-27b.json`。

执行计划在 `configs/cache/adjacent_pilot.json`、`adjacent_contrast.json`、`adjacent_compact.json`。本机重新执行相同计划会跳过账本已登记的请求；不要删除账本以制造新测量。

```powershell
$env:PYTHONPATH = "$PWD/src"
# 以下为离线汇总，不读密钥、不调用模型。
python tools/summarize_adjacent_cache.py --root runs/adjacent_cache_20261018
```

新环境需准备 NIPS 原始快照、先前样本身份和当天端点元数据，不能仅凭计划文件猜测旧数据。不要将真实输入、账本或响应加入 Git。

## 后续选择

本轮足以证明相邻历史复用可以产生真实输入折扣，也确认了当前布局和滑窗的限制，因此停止追加调用。可以优先把紧凑历史在前布局作为版本化候选；合入前应使用更多学生验证增长期与滚动期费用占比、预测指标及实际调度吞吐。暂不改变默认协议，也不根据一次实验宣称某供应商永久最优。
