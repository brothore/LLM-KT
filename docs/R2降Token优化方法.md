# R2降Token优化：方法与验收约束

2026-10-18开始，用户取消R2消融，要求只基于R2进行保持效果的降本优化；本阶段总预算￥1，按美元×7规划换算，独立账本 `runs/r2_cost_optimization_20261018_v1/budget.json`。此前重验预算不混入本阶段。

## 固定任务与效果门槛

所有付费候选均使用四人开发集的492个完整目标，保留全部合法历史、当前题目和原训练fold1–4先验。没有减少学生、截断时间步、缩短历史窗口、加入当前/未来标签或用预测替代真实历史。大验证集暂不调用。

原R2对照：整体AUC 0.7784399815，学生AUC mean 0.7078751914，log loss 0.5763086833。候选须完整覆盖，且整体AUC与学生mean各下降不超过0.01、log loss增加不超过0.02、任一学生AUC下降不超过0.03。门槛是固定四人开发集的工程筛选规则，不是统计非劣效证明；多个候选反复选择存在开发集过拟合。

## 优化维度

1. 精简指令：独立保留一个仅改写指令的候选，与只改数据表示区分；该改动可能影响模型理解，不能因为文字变短就认定保留效果。
2. 对象变数组：历史 `[question_id, concept_ids, correct]`，当前题 `[question_id, concept_ids]`，去掉每条重复字段名。模型说明格式，客户端可精确还原原始对象。
3. 数字ID：仅将规范整数形式的字符串编码成JSON整数，解码恢复字符串。带前导零等ID保留字符串；没有重编号、合并ID或赋予ID数量含义。
4. 逐行历史：每行 `question_id|逗号分隔concept_ids|0或1`，记录间换行，保持时间顺序。包含分隔符的ID明确拒绝，不静默替换。当前题仍单独给出，完全不含当前答案。
5. 证据结构压缩：统计对象可无损编码为 `[n,correct,rate]`，训练global为 `[n,correct,p]`、题目/概念为 `[id,n,correct,p]`。字段对应关系由指令说明；保留全部数值、null和多概念顺序。说明开销可能抵消收益，必须看实测token。
6. 输出压缩：比较原JSON、整数0～10000、小数概率。整数除以10000保留四位小数数值精度；小数输出直接表示概率。两者都严格解析，拒绝额外文字、越界和不完整输出；不能假设输出格式改变不影响校准。
7. 输出上限：简短标量候选max_tokens=16，reasoning关闭。上限降低本身不代表实际输出费用下降，要看completion_tokens，截断不能当成功。
8. 请求调度：可选 `execution.student_serial`，同学生时间步串行、不同学生并发。输入完全不变，上一预测仍不回填历史。记录耗时、请求重叠、cached_tokens与账单，若速度损失大而收益小则不默认启用。

没有采用压缩成base64或其他模型不能可靠直接理解的编码；没有通过省略历史/先验、把多个学生/未来时间步塞进一个可互相看见的上下文来省请求。流式输出和本地预计算统计不会自动降低供应商输入/输出token费用。当前模型此前未查到可用Batch端点，不将未支持的Batch折扣算进收益。

## 缓存和追溯

输入始终保持静态指令、增长历史、当前题及目标相关证据的顺序。相邻前缀可能被供应商缓存；滚动窗口删除最早历史后可能破坏前缀，四人数据最长167条，不能外推长序列滑窗收益。

候选都发出新的请求，不导入旧答案。供应商自动缓存允许利用；它缓存输入计算，不等于复用预测。重复实验可能暖缓存，不能将不同次账单差全部归因于调度。须同时报告input_tokens、completion_tokens、cached_tokens、实际费用与未知费用预留；缺失账单不按零算。

每组先冻结配置、prompt/先验、源prepared及参考结果哈希；逐条解码验证输入和证据与原对象一致，然后才发请求。运行保存request JSON/HTTP body、response JSON/HTTP body、attempt/invocation、SQLite状态、逐学生与整体指标，所有真实数据仅存被Git忽略的runs/data目录。工具入口 `tools/run_r2_cost_optimization.py`，模型模板位于 `configs/prompts/cost_r2_*`。

结论、失败候选、重复对照和最终推荐配置应记录在结果文档，不能只展示费用最小的成功片段。
