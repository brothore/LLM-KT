# Prompt AUC 三轮迭代计划

执行已完成，结果与测试泛化限制见 [Prompt三轮迭代结果](Prompt三轮迭代结果.md)。以下保留运行前的计划与选择约束。

2026-10-18，用户要求先提交已有进度，再验证 Tenstorrent 成本，并至少进行三轮完整 AUC 迭代；每轮必须总结与复盘。此计划在完整基线结果返回前记录。

当前进度已提交为 `a59ecdb`。提交前后敏感扫描通过；未推送在线仓库。真实数据、密钥、请求响应和实验数据库不进入 Git。

## 固定评价协议

使用 NIPS 0.1% 派生数据集，question 级 pykt_window、maxlen=200、真实历史更新。所有候选在相同 fold0 验证集上完整推理（221 目标）；选择以整体 AUC 为主，辅以 logloss、覆盖率、学生 AUC mean/std 与概率分布。标签单类学生 AUC 为 null。保留每条样本身份、输入输出、用量和各阶段哈希。

独立 test 272 目标不参与候选设计或选择。至少三轮结束后才锁定赢家进行一次最终测试；若在 test 上进行基线对照，也只作最终报告，不据此重新选择或继续调参。小样本验证集提升不能直接宣称总体性能显著提升。

## 供应商与预算

同输入小样本上，Tenstorrent 四次约 0.000150340 USD，Chutes 四次约 0.000273080 USD，继续使用 Tenstorrent。它的输出可能有单层 JSON 代码围栏，解析时仅去除这一外壳，保持严格单字段数值校验，原始响应永久保留；没有把多余解释文本当作合法答案。

本轮完整迭代共享持久化 0.40 USD 预算，计入先前约 0.02 USD 探索后仍低于此前 0.50 USD 授权。每次请求先预留，已知费用结算，失败未知费用保留预留。若实际同输入费用比 Chutes 贵，先记录证据并切回；同轮保持端点一致，避免混杂。

## 轮次

- B0：通用 KT 指令、紧凑历史在前 JSON，完整验证集基线。
- R1：根据 B0 的概率分布及分组误差，加入当前题相关的可见历史证据与更明确的预测规则，完整验证并复盘。
- R2：根据 R1 的增益与残余问题选择下一变体。若需要群体难度先验，只能从训练 fold1–4 生成，严格排除 validation fold0 与 test；将其记为训练信息增强，而非纯文字改写。
- R3：基于 R2 与 B0/R1 对照继续修正证据融合或提示规则，完整验证并复盘。无论是否提升，均记录并保留失败候选。

每轮复盘固定包含：假设、变更、完成数、AUC 与上一轮/当前最佳比较、辅助指标、实际费用、残余问题、是否保留，以及下一轮依据。不能在只做少量样本后称作“完整一轮”。目标1的三轮完成前，不以减少输入 token 为主要目标。

## 实现入口

版本化 prompt 文件位于 configs/prompts；model.prompt_file 由配置加载并冻结到运行 manifest，不作为 API 参数发送。历史统计只依赖 ModelInput 的合法历史。输入模板/证据不同会改变请求哈希，不会复用旧候选的预测。

运行复用已有 infer/evaluate/verify-run，额外共享费用账本；成本估算器对新 prompt 按实际渲染文本计算字符代理。工具 run_prompt_experiment.py 编排单轮，analyze_prompt_experiment.py 输出离线分组诊断。
