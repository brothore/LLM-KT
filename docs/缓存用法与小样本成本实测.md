# 缓存用法与小样本成本实测

后续更新：用户授权 0.50 USD 的相邻 KT 目标探索已完成，已经观察到历史前缀命中及真实输入折扣，见 [KT 相邻历史前缀缓存探索](KT相邻历史前缀缓存探索.md)。本文保留较早的相同目标重复测试，不能将其“未命中”外推为后续相邻目标实验结论。

记录日期：2026-10-18。结论：本地结果缓存已验证能避免重复 API 费用；此次服务端 prompt 缓存对照中，Darkbloom 与 Parasail 的重复请求均返回 cached_tokens=0，没有测得输入折扣。端点宣称支持缓存，不代表某个请求必定命中。

## 两种缓存分别解决什么问题

| 缓存 | 重跑时是否请求 API | 缓存的内容 | 主要用途 |
|---|---|---|---|
| 本地结果缓存 | 成功目标不再请求 | 已生成的预测概率及证据 | 中断续跑、重复评估、避免重复付费 |
| 服务端 prompt 缓存 | 仍请求并执行推理 | 可复用输入的计算状态 | 供应商支持时减少部分输入计算与费用 |

本地恢复返回同一次实验的预测，不是新的随机重复实验。服务端命中仍会产生输出费用，也可能有写入费用。不能用本地缓存的零请求证明服务端发生缓存读取。

## 服务端缓存怎么用

### KT 逐步预测能否复用上一请求的历史

这是用户实际关注的生产场景：用 H1…Ht 的真实作答预测当前题，再在下一次请求中加入已经观察到的真实作答，预测下一题。如果请求开头保持逐 token 相同，支持前缀缓存的端点可能复用其中的历史计算，并按缓存读取价计费。每次仍发送完整的协议输入，不需要把“历史已经缓存”理解为可以省略历史。复用的是输入计算，不是上一步预测概率，也不改变真实历史更新规则。

增长阶段可以采用“固定说明 → 历史 → 当前题”的布局，让历史追加前的公共部分尽量保持一致。能复用的是从请求起点连续相同的前缀；仅有大量相同文本、但它们的前面发生变化，并不等价于前缀命中。标点、序列化和 tokenizer 边界也可能使实际复用长度略短于肉眼看到的公共文本。

当前实现的 current_item 在 history 前，当前题变化可能在历史之前就打断前缀；因此尚不能把“KT 有长历史”直接折算成节省。即使把历史放在前面，maxlen=200 对应最多 199 条历史，窗口满后每步会移除最早记录，历史开头改变，后续重叠内容也不再是同一个起始前缀。不能为了缓存改用无限完整历史并声称协议不变。

应另做相邻目标实验：同一学生、相同协议，分别覆盖历史增长期、窗口刚满与窗口滚动期，顺序发送两个或更多目标，检查实际 cached_tokens 与输入费用；对比现有布局和历史在前的候选布局时，必须分别标识模板版本并重新评估概率。此次测量用的是相同目标的完整重复，**没有验证相邻目标的历史前缀是否命中**，也没有实施该布局优化。

### 隐式缓存与显式缓存

本次测试的两个第三方 Qwen 端点声明隐式缓存，发送正常 Chat Completions 请求即可参与其缓存逻辑，没有添加 cache_control，也没有修改历史或填充无关文字。

OpenRouter 文档另有 Alibaba 原生显式缓存的指定模型清单和消息块 cache_control 用法。不能因为模型作者是 Qwen，就把该规则套用到 Darkbloom、Parasail 或任意 Qwen 型号。本项目当前只支持普通字符串消息，尚未实现显式缓存块。

### 固定供应商，减少路由混杂

本次配置在 `configs/cache/nips_qwen_darkbloom.yaml`：

```yaml
model:
  parameters:
    provider:
      only: [darkbloom/fp4]
      allow_fallbacks: false
```

Parasail 使用 `only: [parasail/fp8]`。该设置只限定供应商端点，不保证落到同一后端工作节点或缓存条目；禁用回退也会降低故障恢复空间。该测试配置没有替换默认推理路由。

OpenRouter 提供 session_id 或 x-session-id 的供应商粘性路由；prompt_cache_key 还可作为其回退键。它们帮助同一会话维持路由，并不是缓存开关或命中保证。官方所述粘性会话空闲期限为 10 分钟，不能把它等同于供应商缓存 TTL。当前配置加载器不接受 session_id / prompt_cache_key，本次未添加，后续要使用须独立扩展适配器、配置校验和追溯记录。

### 输入如何保持可复用

前缀缓存通常依赖相同的开头。固定任务说明放在前面，变化内容放在后面，是后续可评估的布局方向。当前 canonical JSON 的 current_item 位于 history 前，会提前打断相邻目标的公共前缀；固定窗口滚动又会删除最早的历史，进一步影响复用。

本次仅测试完全相同请求的重复调用，保持现有输入布局不变，没有把它当成相邻时间目标缓存的测量。不能为提高命中率塞入未来标签、增加协议外历史或无关填充。最小缓存长度、分块粒度、实际 TTL、写入完成时机与后端分配均依赖供应商；本次没有拿到两个端点的完整契约，未把其他厂商的阈值当作它们的规则。

### 确认命中与计费

检查每个真实响应：

```text
usage.prompt_tokens
usage.completion_tokens
usage.prompt_tokens_details.cached_tokens
usage.prompt_tokens_details.cache_write_tokens
usage.cost
usage.cost_details.upstream_inference_prompt_cost
usage.cost_details.upstream_inference_completions_cost
```

cached_tokens > 0 才是返回了缓存读取证据；缺失字段是未知，不能当作 0。cache_discount 如果提供也保留，但本次响应没有该字段。费用以响应记录为依据，字符估算器用于事前预算。

相同输入 token 数下，输入节省可用“无缓存输入 token × 普通单价 − 实际输入费用”检查；已知命中 token 数时，也可按“命中 token ×（普通单价 − 读取单价）”估算。后者没有计入潜在写入或额外费用，必须核对实际账单字段。总费用还包含输出，不应把输出长度变化误算成输入缓存折扣。

## 小样本实测

使用此前已授权的两条 NIPS 真实目标，没有发送学生 ID、当前标签或未来标签。Qwen 关闭 reasoning、temperature=0、max_tokens=256，逐条执行；不同 pass 使用独立 run 目录，让本地缓存不拦截第二次远程调用。每条最多一次尝试，无自动付费重试。

Darkbloom 第一轮两次调用，一次 ConnectError、一次成功。连接失败没有响应，计费状态未知。第二轮两条均成功；共同成功的那一条可进行配对比较。随后在原两条中的一条上，固定 Parasail 做两次对照。

| 端点 / 配对阶段 | 输入 token | 缓存读取 token | 输出 token | 输入费用 USD | 总费用 USD |
|---|---:|---:|---:|---:|---:|
| Darkbloom 首次观察 | 1757 | 0 | 15 | 0.00008785 | 0.00009835 |
| Darkbloom 相同请求重复 | 1757 | 0 | 15 | 0.00008785 | 0.00009835 |
| Parasail 首次观察 | 1747 | 0 | 29 | 0.00026205 | 0.00029105 |
| Parasail 相同请求重复 | 1747 | 0 | 29 | 0.00026205 | 0.00029105 |

两对请求实测输入费用节省均为 **0%**。每个端点内部两次请求的 payload 哈希相同，供应商相同；但首次观察不等于已证明的冷缓存，也没有清空远端缓存。没有足够证据确定未命中的原因。

Darkbloom 还有一条仅在第二轮成功的请求：1794 输入 token、0 命中、14 输出 token，总费 0.00009950 USD，不纳入配对百分比。

本次共 6 次远程尝试、5 次成功，成功响应报告费用合计 **0.00087830 USD**，另一次连接失败费用未知，不能称为精确全账单。重复测量费用也包含在内，不只计算最后一轮。

两个端点各在第二轮 run 上执行一次本地 resume：新增远程请求均为 0，新增 API 费用为 0。根目录 execution_summary 的 known_cost_usd 是累计已知费用，不能把它当作这次零请求恢复的新支出。

这些结果只能说明此次相同输入小样本没有测到远端命中。不能推出供应商永远不缓存、所有 KT 输入不适合缓存，也不能直接外推完整 272 目标数据集的命中率或吞吐。

## 代码、产物与复现

工具 `tools/benchmark_prompt_cache.py` 编排已有 infer，不修改生产协议。限制 1–2 条目标、串行执行、固定单一供应商、关闭回退。保留两个独立 pass 的完整请求响应与 attempt 元数据，按共同成功样本比较，再验证本地 resume 为零请求。中断后重复执行时复用已成功目标，失败保留为失败，不自动增加尝试上限。

```powershell
$env:PYTHONPATH = "$PWD/src"
python tools/benchmark_prompt_cache.py --config configs/cache/nips_qwen_darkbloom.yaml --prepared data/prepared/nips_0p1pct_smoke_v1 --output runs/cache_probe_qwen_darkbloom_20261018_v1
python tools/benchmark_prompt_cache.py --config configs/cache/nips_qwen_parasail.yaml --prepared data/prepared/nips_0p1pct_cache_one_v1 --output runs/cache_probe_qwen_parasail_20261018_v1
```

本机上述实验已完成，再执行同命令会校验并读取已完成实验，不会制造新的远程重复。要启动新测量，应使用新的 output 目录，并留意其付费性质。

各 output 中包括 experiment.json、report.json、artifact_manifest.json 及 pass_1/pass_2。report 的 total_benchmark_cost_usd 当前表示成功响应中可汇总的费用，必须连同 unknown_cost_attempts 阅读；失败成本不按零填充。所有样本、运行记录和中间产物位于 Git 忽略目录，不上传。

新增离线测试验证缓存节省计算、输出费用隔离、未知字段与明确未命中的区别。未来生产优化仍在 TODO：本次没有重排 prompt、改调度、跨学生共享标签或给 Decisions API 套用 Chat 参数。
